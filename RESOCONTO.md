# RESOCONTO – ProFile Manager (Yanagi Academy) – aggiornato al 22/11/2026

## OBIETTIVO
Suite web con login. Gli account li crea solo l'admin, che decide per ogni account (compreso il proprio) lettura/scrittura su ogni sezione e quali account sono admin.
Sezioni: Documenti, Mail, File importanti, Lezioni, Esami, Tecnici, Atleti, Tessere, Eventi (ex Gare), Ordini, Ricevute, Video, Foto, Archivio. In più una Chat.
Barra di ricerca in alto che filtra tutte le sezioni. Data e ora in basso a destra. In ogni sezione c'è il Promemoria in basso.

## DECISIONI
- Hosting: GitHub Pages (https://yanagiacademy.github.io), repository separato da quello di gare.html. Nomi dei file senza prefisso.
- Backend: Firebase (Authentication email/password + Firestore). Moduli ES da CDN gstatic v10.12.2, niente npm. Permessi applicati dal server con firestore.rules. Firebase Storage NON usato (richiede Blaze).
- Telegram: UN SOLO gruppo "YA ProFile Maker" con ARGOMENTI (TG_GROUP = TG_FILES). La Chat usa l'argomento Chat (ex General); ogni sezione ha il suo argomento (Documenti, File importanti, Lezioni, Atleti, Tecnici, Eventi, Video, Foto, Commercialista, Mail, Archivio). Accesso col proprio numero di telefono (GramJS), oppure senza codice con conferma dall'app Telegram (chat.html).
- Contenuti: TUTTO su Telegram (schede, elenchi, note, promemoria di pagina, file); Firebase solo per account/permessi e come copia facoltativa per singolo contenuto (casella "Salva anche su Firebase"). Dettagli nelle sezioni NOVITÀ qui sotto.
- File (Documenti, Lezioni): nel gruppo "YA ProFile Maker", argomento della sezione, limite 500 MB a file. La scheda del file sta nel registro Telegram (fsx.js). Senza Telegram configurato: tutto su Firebase come prima (blocchi max 20 MB).
- Mail: Gmail dell'ASD (account personale) condiviso tramite un "ponte" Google Apps Script: le persone entrano solo col login della suite, non vedono mai la password di Gmail.
- Promemoria di 2 tipi in ogni sezione: "Questa pagina" (modificabile da chi ha la scrittura) e "Tutte le pagine" (uguale in tutta la suite, modificabile solo dall'admin).
- Preferenza: non aggiornare i numeri di versione nei file dei progetti.

## NOVITÀ (22/11) – LEZIONI: ALERT PER LA «PROSSIMA LEZIONE» TRA ADMIN E TECNICI
- RUOLI: TECNICI = quelli registrati nella scheda Tecnici (la mail è quella inserita dall'admin nella scheda; serve anche un account che acceda a Lezioni). Le proposte stanno in Firebase (raccolta lezioniProposte, non passano da Telegram); le vede in «Le mie proposte» (in attesa / accettata / accettata con modifiche / rifiutata + motivo) e finché sono in attesa o rifiutate può correggerle e reinviarle o eliminarle.
- L'ADMIN vede il riquadro «Proposte dei tecnici» in Lezioni (per le modifiche mostra il valore «prima:») e per ciascuna sceglie: ACCETTA (la lezione diventa condivisa, i tecnici sono avvisati), MODIFICA… (apre il modulo con i dati proposti, «Salva e accetta»; il proponente vede «accettata con modifiche»), RIFIUTA (motivo facoltativo, avvisa solo il proponente). Nella Home dell'admin: «Lezioni: N proposte dei tecnici da valutare»; il proponente trova «tue proposte valutate dall'admin».
- MAIL ALL'ADMIN per le proposte: i tecnici non possono usare il ponte Gmail (è solo per l'admin), quindi la mail agli indirizzi admin (Mail → Notifiche) parte alla prima apertura della suite o di Lezioni da parte dell'admin (una sola volta per proposta). L'avviso nell'app è invece immediato.

## NOVITÀ (16/11 sexies) – CORRETTO L'INVIO DEI FILE GRANDI A TELEGRAM (telegram.js)
- PROBLEMA: il Backup si fermava all'invio della prima parte (25 MB) con «Cannot use [object File] as file. / Either one of `buffer` or `filePath` should be specified». Colpiva ogni file sopra circa 20 MB inviato con tgSendFile (backup, video, documenti pesanti); i file piccoli passavano solo grazie al ripiego CustomFile.
- CAUSA: la libreria GramJS (telegram-lib.js) scarta un File del browser che non ha la proprietà «read» (primo errore) e, sopra i ~20 MB, legge un CustomFile da un percorso su disco che nel browser è vuoto (secondo errore).
- CORREZIONE: in tgSendFile il File riceve una proprietà «read» fittizia, così la libreria lo accetta e lo legge in memoria (nessun limite di dimensione). Il ripiego CustomFile resta per i file piccoli. Nessun altro file toccato; numeri di versione non aggiornati.
- Nel Backup «VID-…mp4: MISSING» non è un errore dell'invio: il file risulta nel registro ma non si trova più su Telegram (messaggio cancellato). Viene saltato e finisce in errori.txt dentro il backup.
- DA PROVARE: rifare il Backup con i file (parte da 25 MB e successive) e inviare un video grande da Documenti. Se la pagina restituisce ancora il vecchio errore, aprirla con ?x=N in fondo all'indirizzo (cache).
